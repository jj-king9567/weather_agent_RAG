#  Weather Agent RAG 智能天气助手 （2.0版本）

这是基于原本天气预报进行更新的智能天气问答系统，包含完整的双路检索（RAG）与 Rerank 重排优化链路。

##  核心

- **纯异步前后端分离**：使用 Fetch API 实现页面无刷新天气查询。
- **双路召回架构**：ChromaDB 负责粗排，reranker（base版）负责精准重排。
- **置信度兜底策略**：创键 `SAFE_THRESHOLD` 机制，当 Rerank 模型遇到短文本“降智”（如打出 0.000037 的极低分）时，自动回退至向量召回结果，防止误杀正确答案，提高正确率。

##  优化数据对比 (Baseline vs Rerank)

| 指标 | 纯向量检索 (Baseline) | RAG + Rerank 重排 | 提升策略 |
| :--- | :--- | :--- | :--- |
| **Top-1 召回率** | 40% | **80%** | 引入交叉编码器重排 |
| **典型成功案例** | “穿短袖”误召回“西藏-1度” | “穿短袖”精准召回“南宁25度” | 解决常识推理短板 |

##  踩坑与复盘记录 (Bad Cases)

1. **Rerank 分数极低却排第一**：在RAG测试中发现，模型对“jjk帅吗”这种短文本+非标准词汇极度不自信（置信度仅 0.000037）。为此，我在代码中加入了多路召回兜底逻辑，分数低于 0.1 时回退至向量结果。发现更接近答案
2. **Chunk 切分的教训**：测试weather_agent_chunk发现，切分过长（150字）容易引入无关噪音，过短（30字）则会截断“带伞”与“南宁”的语义。最终确立了以 80 字为佳、重叠 10 字的切分策略。
3. **NumPy 类型报错**：`reranker.predict` 返回的 NumPy 浮点数在 Python 原生 `sorted` 函数中会引发 `ufunc '<'` 报错，必须通过 `float(s)` 强制转换类型。
